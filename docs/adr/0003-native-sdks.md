# ADR-0003: SDK はネイティブ 2 実装とし、共有はゴールデンベクタで担保する

- **状態**: 承認
- **決定日**: 2026-07-30

## 背景

iOS と Android で同じ挙動をする SDK が要る。割当ロジックが両者でずれると、実験結果が静かに壊れる（テストで気づけない種類の障害）。ロジックをどう共有するか。

## 選択肢

| 案 | バイナリ増分(iOS) | ロジック共有 | 導入障壁 |
|---|---|---|---|
| **A. ネイティブ 2 実装（Swift + Kotlin）** | 〜200KB | なし（仕様とテストで担保） | 低 |
| B. Kotlin Multiplatform | +1.5〜3MB | あり | 高（iOS チームの同意が要る） |
| C. Rust コア + UniFFI | 〜400KB | あり | 中〜高（ビルドパイプラインが複雑、書ける人が必要） |

## 決定

**A（ネイティブ 2 実装）** を採用する。ロジックの同一性は共有コードではなく、**規範仕様 + ゴールデンベクタによる適合性テスト**で担保する。

### 根拠

**1. 本当に共有したいものは小さい。**

「両実装がずれると致命的」なのは決定的割当だけで、これは実質数十行しかない（SHA-256 とビッグエンディアン読みと累積レンジ探索）。共有ライブラリで守るより、[golden-vectors.json](../../spec/golden-vectors.json) を全実装の CI で走らせるほうが**直接的で、かつ強力**。共有コードは「同じコードが動いている」ことしか保証しないが、ゴールデンベクタは「同じ答えが出る」ことを保証する。後者が本当に欲しい性質。

本設計の策定時点で、Python / Node / Go の 3 実装が同一のベクタを再現することを確認済み。

**2. バイナリサイズは交渉可能な要件ではない。**

「A/B テスト SDK を入れるとアプリが 3MB 増えます」は iOS チームに拒否される。Kotlin/Native ランタイムのコストは、実験基盤という「アプリの本質的価値ではない機能」に対して正当化しにくい。**導入されない SDK に価値はない。**

**3. 残りのロジックは、そもそも共通化できない。**

キャッシュ・イベント送信・バックグラウンド処理は、各プラットフォームの機構に強く依存する:

| 機能 | iOS | Android |
|---|---|---|
| バックグラウンド送信 | `URLSession` background configuration | `WorkManager` |
| 永続化 | ファイル + Keychain | DataStore + EncryptedSharedPreferences |
| ライフサイクル | `UIApplication` 通知 | `ProcessLifecycleOwner` |

共通化の対象になるのは薄いオーケストレーション層だけで、KMP の対価に見合わない。

## 帰結

### 必須の統制（これがないとこの決定は成立しない）

1. [spec/bucketing.md](../../spec/bucketing.md) を**規範仕様**とする。実装はこれに従う。
2. 全実装（Swift / Kotlin / Go / Python / TypeScript）が [golden-vectors.json](../../spec/golden-vectors.json) を CI で検証し、**不一致ならマージをブロック**する。
3. ゴールデンベクタは段階別に照合可能な形（`sha256_prefix_hex` / `uint32_be` / `bucket`）にし、不一致時に原因箇所を特定できるようにする。
4. 新しいターゲティングオペレータを追加するときは、**両実装を同一 PR で更新する**ことをレビュー規約にする。片方だけ実装された状態を作らない。
5. 前方互換テスト（未知のフラグ型・未知のオペレータで安全側に倒れること）を両実装で必須にする。

### 再検討のトリガ（あらかじめ決めておく）

以下のいずれかが起きたら B（KMP）を再評価する:

- SDK のコア部分が 5,000 行を超えた
- 両実装の挙動差に起因するバグが 2 件以上発生した
- ターゲティングオペレータの追加が四半期に 2 回以上発生し、二重実装が開発速度のボトルネックになった

**この決定は「KMP が悪い」ではなく「現時点の規模ではネイティブのほうが総コストが低い」という判断。** 規模が変われば結論は変わる。
