# 01. 要求仕様

## 1. スコープ

| 含む | 含まない（当面） |
|---|---|
| フィーチャーフラグ配信（段階的ロールアウト、キルスイッチ） | ビジュアルエディタ（コード変更なしの UI 差し替え） |
| A/B/n テスト（クライアント側・サーバ側の両方） | パーソナライゼーション／バンディット最適化（Phase 3 で検討） |
| 被験者の決定的割当・排他制御（レイヤー） | プッシュ通知配信そのもの |
| 曝露（exposure）／メトリクスイベント収集 | BI ダッシュボード汎用機能（既存 BI に委譲） |
| 統計解析・有意差判定・ガードレール監視 | MMP（アトリビューション）機能 |

## 2. アクター

| アクター | 主なユースケース |
|---|---|
| プロダクトマネージャ | 実験の設計・開始・停止、結果の解釈 |
| クライアントエンジニア | SDK 組み込み、フラグ分岐の実装、QA |
| サーバエンジニア | サーバ側実験、バックエンドフラグ |
| データサイエンティスト | メトリクス定義、統計手法の検証、深掘り分析 |
| SRE | キルスイッチ、ガードレールによる自動停止 |

## 3. 機能要求

### 3.1 実験管理
- 実験の CRUD、下書き → レビュー → 開始 → 停止 → アーカイブのライフサイクル。
- バリアント定義（`control` / `treatment` …）と、バリアントごとの**パラメータ**（JSON）。フラグは「bool を返すもの」ではなく「型付き設定値の束を返すもの」として扱う。
- ターゲティング条件: アプリバージョン、OS バージョン、プラットフォーム、国／言語、ユーザ属性、既存セグメント、ランダム抽出。
- **レイヤー（排他グループ）**: 同一レイヤー内の実験は被験者が重複しない。レイヤーをまたぐ実験は直交して重複割当される。
- **ホールドバック**: 全実験から除外される恒常的な対照群（累積効果の測定用）。
- 相互排他だけでなく**依存関係**（実験 B は実験 A の treatment のみを対象）も表現できること。

### 3.2 割当
- 決定的であること。同一 `(unit_id, experiment, seed)` は常に同一バリアント。サーバ・クライアント・分析基盤で完全一致すること。
- ランダム化単位を実験ごとに選択可能: `install_id` / `user_id` / `account_id` / `session_id`。
- 再ランダム化（seed 更新）で過去の割当と独立な割当を得られること。
- **スティッキー割当**: 一度割り当てたら、対象条件から外れても（例: ロールアウト率を下げた）バリアントを維持するモードを選択可能にする。

### 3.3 SDK
- 同期 API で必ず値が返る（初期化後に `nil` を返さない）。
- 初期化がアプリ起動をブロックしない。
- オフラインで動作する。
- 曝露イベントを評価時に自動送出し、セッション内で重複排除する。
- QA 用のバリアント強制上書き（ディープリンク／デバッグメニュー）。

### 3.4 解析
- 実験ごとのメトリクス自動集計、信頼区間付きの効果推定。
- SRM（Sample Ratio Mismatch）検知を**結果表示のハードゲート**とする。
- ガードレールメトリクス違反時のアラートと自動停止。
- 分位点メトリクス（p50/p95 のレイテンシ等）と比率メトリクス（CVR 等）の双方に対応。

## 4. モバイル固有の制約（本設計の中核）

Web の実験基盤をそのままモバイルに持ち込むと必ず破綻する。以下がその理由であり、後続の設計判断のほぼすべてがここに由来する。

### C1. バリアントのコードはバイナリに同梱されている
サーバでレンダリングする Web と異なり、モバイルの treatment 実装は**リリース済みのアプリバイナリの中にしか存在しない**。コンフィグは「既に存在するコードパスのどれを通すか」を切り替えるだけ。

**帰結:**
- 実験開始前にコードをリリースしておく必要がある（フラグ off の状態で先行リリース）。
- 実験対象を「そのコードを含むアプリバージョン以降」に限定する**バージョンターゲティングが必須**。
- 古いバージョンのアプリが未知のフラグ／未知のバリアントを受け取った場合、**必ず安全側（control 相当のデフォルト）にフォールバック**しなければならない。前方互換性は SDK の必須要件。

### C2. アプリバージョンの普及に数週間かかる
コードのロールバックにストア審査が挟まる。デプロイで戻せない。

**帰結:**
- リモートのキルスイッチが唯一の緊急停止手段。コンフィグ配信の可用性は**アプリの可用性そのもの**であり、SLO は最高ランクになる。
- フラグは長寿命化する（最古のサポートバージョンが消えるまで消せない）。フラグの棚卸しプロセスを運用に組み込む必要がある。

### C3. アプリバージョン間の混在は交絡する
実験期間中にアプリの新バージョンが配信されると、「新バージョンへ早く更新するユーザ」という偏った集団が混入する。

**帰結:** 解析時にアプリバージョンを共変量として扱う、もしくはバージョン固定で解析する。バージョン別のブレイクダウンを標準出力にする。

### C4. イベントは遅延到着し、順序も保証されない
電波の無い環境、バックグラウンド送信の制約（iOS の Background Task は実行タイミングが OS 依存）、アプリを数日開かないユーザ。

**帰結:**
- クライアント側で永続キューに貯め、再送する（at-least-once）。
- サーバ側で `event_id` による冪等な重複排除が必須。
- 解析パイプラインは**遅延到着データを前提に再計算する**。7 日のウォーターマーク、14 日で確定。
- 「イベントが来ない = ユーザが行動しなかった」ではないため、送信済み判定に使えるハートビートが要る。

### C5. 端末時刻は信用できない
ユーザが手動で時刻を変更でき、タイムゾーンも移動する。

**帰結:** バッチ単位でサーバ受信時刻との差分（skew）を推定し補正する。単調増加クロック（`uptime`）を併送してバッチ内の順序を復元する。

### C6. 起動直後にコンフィグがまだ無い
初回起動時、あるいはコールドスタートでフェッチ完了前に評価が走る。

**帰結:**
- ビルド時にデフォルトコンフィグをバイナリに同梱する。
- 「初回セッションから効かせたい実験」と「2 回目以降でよい実験」を仕様上区別する。前者はバイナリ同梱コンフィグでのみ実施可能（＝リリース時に確定している必要がある）。
- フェッチ未完了で評価された曝露は、その旨を `reason` に記録し解析で区別できるようにする。

### C7. プライバシー制約
IDFA は ATT 同意なしに使えず、Android の広告 ID もオプトアウト可能。`ANDROID_ID` などのデバイス識別子は使うべきでない。

**帰結:** 自前で採番したインストールスコープの ID（`install_id`）を使う。iOS の Privacy Manifest（`NSPrivacyAccessedAPITypes`）と Google Play の Data Safety 申告に必要な情報を SDK 側で文書化して提供する。

### C8. アプリのサイズと起動時間はプロダクト KPI
SDK が重ければ導入が拒否される。

**帰結（予算として明示する）:** バイナリ増分 < 300KB（圧縮後）、`start()` のメインスレッド占有 < 10ms、コンフィグをメモリに常駐させるサイズ < 1MB。

## 5. 非機能要求

| 項目 | 目標 |
|---|---|
| コンフィグ取得レイテンシ | p50 < 30ms / p99 < 150ms（CDN エッジ） |
| コンフィグ配信 可用性 | 99.99%（CDN + 静的フォールバック。オリジン全損でも古いコンフィグを配り続ける） |
| 実験の反映時間 | 公開操作から全エッジ反映まで < 60 秒 |
| キルスイッチ反映 | 端末が次回フォアグラウンド遷移時（＝実効的に数分以内） |
| イベント受信 可用性 | 99.9%（受理優先。バックプレッシャ時も 202 を返しディスクに退避） |
| イベント欠損率 | < 0.1%（送信到達ベース） |
| 解析結果の更新頻度 | 1 時間ごと（速報）／ 日次（確定） |
| 同時実行実験数 | 200（レイヤーによる排他込み） |
| SDK 初期化 | メインスレッド < 10ms、I/O は非同期 |

## 6. 明示的な非目標

- **リアルタイム割当 API を主経路にしない。** 端末内評価が原則（[ADR-0002](adr/0002-local-evaluation.md)）。
- **完全な exactly-once 配送を追わない。** at-least-once + 冪等な重複排除で代替する。コストに見合わない。
- **秘匿情報をコンフィグに載せない。** 配信コンフィグはクライアントに丸ごと渡るため、実験名・パラメータはすべて公開情報とみなす。未発表機能のコードネームを含めない運用ルールが要る。
