bakuchi は iOS / Android を第一級市民として扱う A/B テストプラットフォームの設計です。各フェーズはそれ単体で価値を出して終われるように切ってあります。このページはその段階的構築計画を、時間軸と領域軸の二面から可視化します。

ロードマップを見る 出典の Markdown

フェーズのタイムライン

横軸は Phase 0 開始からの経過週。濃い区間は最短・最長のどちらのシナリオでもそのフェーズに入る期間、淡い区間は開始・終了が前後しうる幅です。Phase 3 は終わりを定めない継続フェーズ、Phase 4 以降は要否が未定の候補です。

確定区間 前後しうる範囲 候補（要否未定）

各フェーズの中身

成果物だけでなく、意図的にやらないことと完了条件を各フェーズに明記しています。作り込みすぎを防ぐ制約は、計画のうち最も守られにくい部分です。

ケイパビリティ導入マップ

同じ計画を領域の軸で見たもの。「いつ何が入るか」と、同じ領域が複数フェーズにまたがって育つこと（統計判定は手動集計 → stats-service → 逐次検定、イベント基盤は単純コンシューマ → Flink）が読み取れます。

リスクと対処

それぞれのリスクは、どのフェーズの仕組みで打ち消すかまで対応づけてあります。

設計判断と未決着の論点

roadmaps/ の BK 項目を、それが効くフェーズに紐づけたもの。フェーズは各項目が明記しているものだけを引いています。可決済みの判断はフェーズの前提、提案中の論点はそのフェーズを始める前に決めるべきことです。
